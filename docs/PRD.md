## 1. 产品定位

**本地优先、秒开、大文件不卡的 Windows Markdown 阅读器。**

核心形容词：轻、快、干净。用户装完就能双击 `.md` 打开，不需要建库、不需要配置、不需要注册账号。

### 1.1 差异化

| 现有工具 | 它的主业 | 我们的切口 |
|---|---|---|
| Typora | 所见即所得编辑 | 阅读体验更深：大纲、进度、多配色、导出 |
| Obsidian | 知识库与双链 | 更轻、秒开、不强制 Vault 概念 |
| VS Code | 开发者工具链 | 面向非技术用户，零配置开箱即用 |
| 浏览器 Markdown 插件 | 寄生在浏览器 | 独立应用、文件关联、原生窗口体验 |

### 1.2 明确的非目标

| 功能 | 排除轮次 | 排除原因 |
|---|---|---|
| Git 版本 | v3.0 | 用户决定移除 |
| 朗读与专项无障碍 | v3.0 | 用户决定移除 |
| 全文搜索 | v3.0 | 用户决定移除 |
| 所见即所得编辑 | v3.1 | 只做源码模式，不做富文本编辑 |
| 双链 / 反链 / 关系图谱 | v1.0 | 与「轻」冲突，归 Obsidian 领地 |
| 云同步 | v1.0 | 引入账号与网络依赖 |
| 插件系统 | v1.0 | 首期不建生态 |
| 演示模式 | v1.0 | Marp 式幻灯片，需求不迫切 |
| 账号体系 | v1.0 | 与本地优先冲突 |

> **无障碍的处理**：随「朗读与无障碍」模块一并移除专项无障碍功能（屏幕阅读器深度适配、朗读、高对比度模式）。但**基础键盘可达性**（Tab 导航、焦点可见、Esc 关闭弹层）与**字号缩放**（Ctrl + 滚轮）作为通用质量要求保留，不单列模块与验收项。

## 2. 关键决策

### 2.1 已锁定

| # | 决策项 | 结论 | 连带约束 |
|---|---|---|---|
| 1 | 技术栈 | Tauri 2（Rust + 系统 WebView2） | 需补齐 Rust / MSVC / Windows SDK（见 §8） |
| 2 | 界面语言 | **中英双语** | i18next + react-i18next，全部文案外置（v2.1「仅中文」作废） |
| 3 | 默认语言策略 | **跟随系统语言，手动切换后记忆选择** | 首次启动读系统区域设置；用户切换后写入配置库，后续以用户选择为准 |
| 4 | 首版范围 | P0 共 9 个 + 扩展 9 个 = **18 个模块** | 见 §3、§4 |
| 5 | 配色主题 | **4 套配色 × 明暗两版 = 8 种组合** | CSS 变量驱动；每套配色须覆盖代码高亮、Mermaid、KaTeX |
| 6 | 表格「全部显示」 | **表格内自适应换行模式** | 不弹层、不开新窗口，在原文位置切换 |
| 7 | 轻量编辑 | **保留，源码模式，默认隐藏** | 点击编辑按钮才进入；应用具备写文件权限，必须配套安全三件套 |
| 8 | 发布节奏 | 核心先行，分批改版 | 先发阅读核心版，扩展功能逐批补齐 |
| 9 | 环境准备 | 安装 Rust + MSVC 全套 | 开工前的前置任务，见《环境准备.md》 |

### 2.2 决策影响说明

- **决策 2 推翻了 v2.1 的「不搭 i18n 框架」**：全部界面文案必须外置为语言资源文件，后续新增功能一律不得硬编码文案。越晚改代价越大，因此 v0.1 骨架阶段就要把 i18n 接进去。
- **决策 5 是主题模块的升级而非新增模块**：3.7 由「主题与排版」改为「主题、排版与配色」。明暗切换保留，配色从 1 套扩到 4 套，最终呈现 8 种组合。代价是配色矩阵的验证工作量从 2 种涨到 8 种。
- **决策 6 放弃了弹层与独立窗口方案**：表格「全部显示」在原文位置切换，实现最轻、不打断阅读流，但垂直占用会变高，需要在视觉上做区分（如切换后表格加边框与阴影以示脱离正文流）。
- **决策 7 使安全三件套重新生效（重要）**：移除 Git 写操作后，**轻量编辑成为应用中唯一会改动用户 Markdown 文件的功能**。因此 v2.1 的**原子写入 / `.bak` 备份 / 外部变更检测**三件套重新生效，并继续作为该模块的发布前置条件。其余 14 个模块一律只读。
- **移除三项带来的收益**：libgit2 约 2.5 MB、TTS 与全文索引逻辑随之省去；体积目标从 v2.1 的 ≤ 35 MB 下调回 ≤ 20 MB，内存从 ≤ 200 MB 下调回 ≤ 150 MB；冷启动压力大幅缓解，懒加载组件只剩 mermaid、KaTeX、CodeMirror 三项。

## 3. 核心功能（P0）— 9 个模块

首版必做，是产品成立的地基。

### 3.1 文件关联打开

- 安装时注册 `.md` / `.markdown` 文件关联，可设为默认打开方式
- 支持拖放文件到窗口打开
- 资源管理器右键菜单「用 MD 阅读器打开」
- 最近打开文件列表（最多 20 条）
- 卸载时自动清除注册表关联

**验收标准**：装完即可双击打开；卸载后不残留无效关联。

### 3.2 GFM 全量渲染

- CommonMark 0.31 规范全量支持
- GFM 扩展：表格、任务列表、删除线、自动链接、脚注
- 内嵌 HTML 支持（设置项，默认关闭以保证安全）
- 危险内容过滤：`<script>`、`on*` 事件属性、`javascript:` 协议一律剥离

**验收标准**：通过 CommonMark 0.31 官方测试集 + GFM 扩展测试集。

### 3.3 代码高亮

- 支持 100+ 语言
- 行号显示、一键复制、超长行横向滚动
- 代码主题跟随当前配色（8 种组合各配一套代码高亮）

**验收标准**：单个 10 万字符代码块渲染与滚动不卡帧。

### 3.4 图片与相对路径

- 支持 `./img/a.png`、`../assets/x.jpg` 等相对路径
- 支持绝对盘符路径（`C:\...`、`D:\...`）
- 支持 `file://` 协议与 http(s) 网络图片
- 图片加载失败显示占位符

**验收标准**：md 文件与其同级图片目录一起移动后，相对路径仍能正确解析。

### 3.5 大纲目录导航

- 自动解析 H1–H6 生成可折叠大纲
- 滚动时高亮当前所在章节
- 点击大纲项平滑跳转

**验收标准**：滚动高亮项与实际视口顶部标题的误差 ≤ 1 个标题。

### 3.6 阅读进度

- 顶部细进度条，实时反映阅读位置
- 关闭文件时记录滚动位置，下次打开自动恢复
- 一键回到顶部

**验收标准**：重新打开文件回到上次位置，误差小于一屏。

### 3.7 主题、排版与配色（v3.1 锁定）

| 项 | 内容 |
|---|---|
| 能力 | **配色主题：4 套**（经典 / 纸感 / 护眼 / 极夜）<br>**明暗模式：每套配色各含浅色与深色两版，共 8 种组合**，另可设为跟随系统<br>排版可调：正文字体、字号、行高、正文最大宽度<br>代码高亮、Mermaid 图表、数学公式均跟随配色联动 |
| 技术选型 | CSS 自定义属性驱动，切换时仅改根节点 `data-theme` 与 `data-scheme` 值，不重建 DOM |
| 工作量 | 小到中（CSS 工作量为主，但 8 种组合 × 三类第三方组件的验证矩阵不小） |
| 风险 | 低。主风险是配色与代码高亮、Mermaid、KaTeX 的联动遗漏 |
| 应对 | 所有颜色一律引用 CSS 变量，禁止硬编码；每套配色上线前跑一遍「代码 + 图表 + 公式」联合检查清单 |
| 验收标准 | 切换配色与明暗均 ≤ 100 ms、无闪烁、不触发文档重新渲染；**8 种组合下代码高亮、Mermaid、KaTeX 全部正确着色且对比度达标**；重启后保持上次选择 |

**4 套配色的基准色值**（关键 token，实现时扩展为完整变量表）

| 配色 | 版本 | 背景 | 正文 | 强调色 | 代码高亮主题 |
|---|---|---|---|---|---|
| 经典 | 浅 | `#FFFFFF` | `#1F2328` | `#0969DA` | GitHub Light |
| 经典 | 深 | `#0D1117` | `#E6EDF3` | `#4493F8` | GitHub Dark |
| 纸感 | 浅 | `#FAF7F0` | `#2E2A24` | `#B45309` | 暖调浅色（自调） |
| 纸感 | 深 | `#23201B` | `#EDE8DF` | `#D9A05B` | 暖调深色（自调） |
| 护眼 | 浅 | `#F5F7F2` | `#2C3328` | `#4F7942` | 低饱和浅色（自调） |
| 护眼 | 深 | `#1A1F1A` | `#DDE5D8` | `#7FA96B` | 低饱和深色（自调） |
| 极夜 | 浅 | `#F7F8FA` | `#10131A` | `#4C6FFF` | 高对比浅色（自调） |
| 极夜 | 深 | `#0B0E14` | `#C8D0E0` | `#6B8AFD` | 高对比深色（自调） |

> 色值可调整。正文与背景的对比度须 ≥ 4.5:1（WCAG AA），强调色用于链接、选中态与活动指示器。

### 3.8 导出

- 导出 PDF：带目录书签，分页不切断标题
- 导出 HTML：自包含单文件（图片转 base64 内嵌）
- 导出 Markdown：原样复制（用于另存）
- 导出结果应用当前配色主题，或提供「始终用浅色导出」选项

**验收标准**：导出结果与原屏幕渲染视觉一致度 ≥ 95%。

### 3.9 文件库侧栏

- 可打开任意文件夹作为「库」，左侧显示目录树
- 支持展开 / 折叠、按文件名过滤
- 收藏夹（置顶常用文档）
- 监听文件夹变化，新增 / 删除文件自动刷新

**验收标准**：打开文件夹即刻入库，万级文件量下侧栏不卡。

> **说明**：文件库侧栏只做**文件名过滤**，不做全文内容搜索（全文搜索已在 v3.0 移除）。

## 4. 扩展功能 — 6 个模块

### 4.1 Mermaid 图表

| 项 | 内容 |
|---|---|
| 能力 | flowchart、sequence、class、state、er、gantt、pie 全类型支持；图表配色跟随当前主题；导出 SVG / PNG |
| 技术选型 | mermaid.js（动态 import 懒加载） |
| 工作量 | 小 |
| 风险 | 低。主风险是大图渲染阻塞主线程 |
| 应对 | 懒加载 + 渲染防抖；渲染失败显示错误块而非崩溃 |
| 验收标准 | 50 节点 flowchart 渲染 ≤ 300 ms；连续切换文档不内存泄漏；8 种配色组合下图表均正确着色 |

### 4.2 数学公式

| 项 | 内容 |
|---|---|
| 能力 | 行内 `$...$` 与块级 `$$...$$`；宏定义；渲染失败显示原始 LaTeX 并标红 |
| 技术选型 | KaTeX（比 MathJax 快 5–10 倍，无异步重排） |
| 工作量 | 小 |
| 风险 | 低。主风险是 `$` 与普通文本、代码块内 `$` 的误判 |
| 应对 | 代码块与行内代码内一律不解析公式；转义 `\$` 优先级最高 |
| 验收标准 | 含 200 处公式的文档渲染 ≤ 500 ms；公式与正文基线对齐无跳动；深浅两版下均清晰可读 |

### 4.3 表格增强

| 项 | 内容 |
|---|---|
| 能力 | 宽表横向滚动 + 表头冻结；**「全部显示」自适应换行模式**；点击表头列排序；复制为 Markdown / TSV / CSV；斑马纹与行号列 |
| 技术选型 | 原生 DOM + CSS `position: sticky` |
| 工作量 | 小 |
| 风险 | 低。超大表格可能拖慢渲染 |
| 应对 | 超过 1000 行的表格启用虚拟滚动 |
| 验收标准 | 200 列宽表横向滚动流畅；表头在滚动中保持可见；复制结果粘贴到 Excel 正确分列 |

**「全部显示」模式（v3.1 锁定为表格内自适应换行）**

针对宽表横向滚动仍看不全的问题：表格右上角提供「全部显示」开关，点击后**在原文位置**把表格切换为自适应换行模式，不弹层、不开新窗口。

| 项 | 内容 |
|---|---|
| 切换行为 | 表格宽度约束为容器宽度，列宽按内容自适应压缩至最小可读宽度，单元格内容自动换行 |
| 视觉区分 | 切换后表格加边框与阴影，示意其脱离正文流；顶部显示「全部显示中」提示条 |
| 配套能力 | 表头保持冻结；列排序可用；导出 CSV；跟随当前配色 |
| 退出方式 | 再次点击「全部显示」恢复横向滚动模式；切换文档或重启后恢复默认（横向滚动） |
| 性能约束 | 超过 1000 行的表格在换行模式下仍启用虚拟滚动 |

**验收标准**：200 列表格在换行模式下所有列均可完整阅读、无横向滚动条；切换耗时 ≤ 150 ms 且不引起页面跳动；单元格换行后行高自适应，无内容截断。

### 4.4 多标签分屏

| 项 | 内容 |
|---|---|
| 能力 | 多文档标签页；左右分屏，各栏独立滚动或按比例同步滚动；拖拽文件到指定栏打开 |
| 技术选型 | 前端状态管理（Zustand / React Context） |
| 工作量 | 中 |
| 风险 | 低。主要是布局状态与滚动同步的边界情况 |
| 应对 | 同步滚动按标题锚点对齐而非像素对齐，避免错位 |
| 验收标准 | 同时打开 20 个标签不卡；分屏切换布局无闪烁；标签顺序与关闭状态持久化 |

### 4.5 阅读记忆

| 项 | 内容 |
|---|---|
| 能力 | 记录每篇文档的最后阅读时间、累计阅读时长、阅读次数、最后滚动位置；侧栏「最近阅读」列表 |
| 技术选型 | SQLite，与配置同库 |
| 工作量 | 小 |
| 风险 | 低 |
| 应对 | 阅读时长按窗口聚焦时长统计，后台不计时 |
| 验收标准 | 位置恢复误差 < 一屏；统计数据重启后不丢失；文件被删除后对应记录自动清理 |

### 4.6 中英双语

| 项 | 内容 |
|---|---|
| 能力 | 界面文案支持简体中文与英文；**首次启动跟随 Windows 系统语言**；用户手动切换后立即持久化，后续以用户选择为准；切换即时生效无需重启 |
| 技术选型 | i18next + react-i18next；文案资源 `locales/zh-CN.json`、`locales/en-US.json` |
| 工作量 | 小到中（约 150–250 条文案 + 布局适配） |
| 风险 | **中。英文文案平均比中文长 30%–50%，按钮、侧栏、设置项存在撑破布局的风险** |
| 应对 | 容器一律弹性布局，禁止固定宽度；英文文案单独做一轮布局走查；缺失 key 时回退中文并记录告警 |
| 验收标准 | 切换语言即时生效且无需重启；界面文案缺失率 0；英文界面下无文字截断、无布局溢出；语言偏好持久化；系统语言为英文时首次启动即为英文界面 |

> **文档内容不翻译**：本模块只翻译应用界面，不翻译用户打开的 Markdown 文档内容。

### 4.7 轻量编辑（源码模式，默认隐藏）

| 项 | 内容 |
|---|---|
| 能力 | 编辑 Markdown 源文件；左文右预览或上下分栏；Markdown 语法高亮；自动补全标题 / 列表 / 代码块 |
| 默认状态 | **默认不显示编辑器**。工具栏提供「编辑」按钮，点击后才加载 CodeMirror 并进入编辑模式；再次点击或按 Esc 退出返回纯阅读 |
| 技术选型 | CodeMirror 6 + Markdown 语言包（懒加载，首次点击编辑按钮时才加载） |
| 工作量 | 中 |
| 风险 | **高。这是应用中唯一具备写用户文件权限的模块，存在数据损坏风险** |
| 强制配套能力 | 脏状态提示（标题栏圆点）、Ctrl+S 保存、**原子写入**（临时文件 + 重命名）、保存前自动生成 `.bak`、外部文件变更检测并提示、每 30 s 自动保存（可关）、撤销栈 |
| 验收标准 | 连续编辑保存 100 次无文件损坏；断电模拟测试中最多丢失 30 s 内的修改；外部修改文件时必须弹窗提示；保存后文件内容与编辑器内容字节一致；未点击编辑按钮时不加载任何编辑器代码 |

> **安全前置条件（缺一不发布）**：原子写入、`.bak` 备份、外部变更检测。
>
> **明确不做**：所见即所得富文本编辑、图片拖拽上传、表格可视化编辑、协同编辑。

### 4.8 图片灯箱

| 项 | 内容 |
|---|---|
| 能力 | 点击正文图片打开灯箱；滚轮 / 按钮缩放；按住拖动平移；「适应窗口 / 原始大小」一键切换；同文档内多图左右切换；底部显示文件名与像素尺寸；Esc 或点击背景关闭 |
| 技术选型 | 原生 DOM + CSS `transform`，**不引入第三方库**（省体积） |
| 工作量 | 小 |
| 风险 | 低。主风险是超大图（10 MB+）解码卡顿 |
| 应对 | 打开前先展示已加载的缩略图占位，原图解码完成后再替换；SVG 走内联渲染，支持无损缩放 |
| 验收标准 | 10 MB 图片打开 ≤ 500 ms；缩放与平移稳定 60 fps；SVG 放大至 800% 不失真；灯箱跟随当前配色（深色背景下图片不刺眼） |

> **明确不做**：图片标注、裁剪、旋转保存、幻灯片自动播放。

### 4.9 全局快捷键

| 项 | 内容 |
|---|---|
| 能力 | 提供覆盖全部常用操作的键盘键位；设置页内以表格形式完整列出所有键位 |
| 技术选型 | 前端全局键盘事件监听，与 Tauri 菜单快捷键绑定 |
| 工作量 | 小 |
| 风险 | 低。主风险是与系统或浏览器默认行为冲突 |
| 应对 | 编辑态下接管 `Ctrl+S` 等会触发浏览器默认行为的组合键；键位冲突在实现阶段逐一验证 |
| 验收标准 | 键位表中每一项均可用且行为正确；编辑态下 `Ctrl+S` 不触发浏览器保存网页；设置页列出的键位与实际行为 100% 一致 |

**键位表**

| 键位 | 功能 | 键位 | 功能 |
|---|---|---|---|
| `Ctrl+O` | 打开文件 | `Ctrl+P` | 导出 PDF |
| `Ctrl+Shift+O` | 打开文件夹为库 | `Ctrl+Shift+P` | 导出 HTML |
| `Ctrl+W` | 关闭当前标签 | `Ctrl+B` | 切换文件库侧栏 |

### 4.10 页内查找

| 项 | 内容 |
|---|---|
| 能力 | 当前文档内关键词查找；上一处 / 下一处跳转；匹配总数与当前序号统计；当前项高亮、其余项淡高亮；区分大小写与全词匹配（可选开关）；Esc 或点击关闭收起查找框 |
| 触发方式 | `Ctrl+F` 打开；`Ctrl+G` / `Ctrl+Shift+G` 跳转下一处 / 上一处；`Esc` 关闭 |
| 技术选型 | 逐个匹配文本节点 + `<mark>` 包裹高亮，或用 CSS Custom Highlight API（WebView2 支持则优先用，性能更好、不污染 DOM） |
| 工作量 | 小（约 1 天） |
| 风险 | **中。大文档（5 MB）下全量高亮可能卡帧；渲染结果为富 HTML 时，匹配需跨越元素边界** |
| 应对 | 5 MB 以上文档改为「增量查找」：只高亮当前视口附近 ±2 屏的匹配项，滚动时动态更新；跨元素边界的匹配按文本节点的字符偏移合并处理 |
| 验收标准 | 5 MB 文档首次查找响应 ≤ 300 ms；跳转定位准确，当前项自动滚动进视口；跨行内元素（如 `**加粗**` 中间的关键词）的匹配不漏；关闭查找后高亮完全清除，不留残留样式 |

> **说明**：本模块只做**当前文档内**查找，不做跨文件的全文搜索（该模块已在 v3.0 移除）。

## 5. 技术方案

### 5.1 分层架构

| 层 | 技术选型 | 职责 |
|---|---|---|
| 渲染前端 | React + Vite | 视图、标签页、大纲、设置、主题、多语言 |
| Markdown 管线 | markdown-it | 解析 → AST → HTML，插件化扩展 |
| 增强渲染 | highlight.js、mermaid.js、KaTeX | 代码高亮、图表、公式 |
| 国际化 | i18next + react-i18next | 界面中英双语 |
| 编辑器 | CodeMirror 6 + Markdown 语言包 | 源码模式编辑，懒加载，默认不加载 |
| 原生侧（Rust） | Tauri 2 core / plugins、rusqlite | 文件读写与监听、导出、文件关联、系统托盘 |
| 存储 | SQLite | 阅读记忆、收藏、配置、语言与主题偏好 |

> **v3.0 移除的依赖**：`git2-rs` / libgit2（随 Git 模块移除）、Web Speech TTS（随朗读移除）。SQLite 保留但不再承载全文索引。CodeMirror 6 因 v3.1 确认保留编辑而重新纳入，但严格懒加载。

### 5.2 Rust 侧接口面

| 命令组 | 用途 |
|---|---|
| `read_file` / `write_file` | 文件读写（写入仅由轻量编辑模块调用，必须走原子写入） |
| `list_dir` / `watch_dir` | 目录树与变更监听 |
| `export_pdf` / `export_html` | 导出 |
| `get_config` / `set_config` | 配置、阅读记忆、语言与主题偏好持久化 |

> **写权限收敛**：全应用仅 `write_file` 一处会改动用户的 Markdown 文件，且只由轻量编辑模块在用户显式点击编辑按钮后调用。其余 14 个模块与所有命令一律只读。

### 5.3 体积预算与懒加载

| 组件 | 估算体积 | 加载策略 |
|---|---|---|
| Tauri 2 基础 | 3–5 MB | 常驻 |
| React + markdown-it + highlight.js | ~0.4 MB | 首屏 |
| i18n 语言资源（中英） | < 0.1 MB | 首屏（仅加载当前语言） |
| 4 套配色（CSS 变量） | < 0.05 MB | 首屏 |
| mermaid.js | ~1.2 MB | **懒加载**（首遇 mermaid 代码块时） |
| KaTeX + 字体 | ~0.3 MB | **懒加载**（首遇公式时） |
| CodeMirror 6 | ~0.5 MB | **懒加载**（首次点击编辑按钮时） |
| 图片灯箱 | < 0.02 MB | **懒加载**（首次点击图片时） |
| 全局快捷键 | < 0.01 MB | 首屏（纯逻辑，无资源） |
| 页内查找 | < 0.02 MB | **懒加载**（首次按下 Ctrl+F 时） |
| SQLite | ~0.8 MB | 常驻 |
| **合计（安装包，压缩后）** | **约 13–19 MB** | — |

> **体积目标 ≤ 20 MB**（由 v2.1 的 ≤ 35 MB 下调）。预算偏紧，CodeMirror 回补后余量不足 7 MB，若后续再增依赖需重新评估。冷启动 ≤ 1 s 不变，靠 mermaid / KaTeX / CodeMirror 三项懒加载守住首屏。

### 5.4 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 开发环境三项全缺（§8） | 无法开工 | 见《环境准备.md》 |
| Win10 未预装 WebView2 | 首启动白屏 | 安装包内嵌 Evergreen Bootstrapper，离线环境附 Offline Installer |
| 英文文案撑破布局 | 界面破损 | 弹性布局 + 禁止固定宽度 + 英文专项走查 |
| 8 种配色组合联动遗漏 | 视觉割裂 | 颜色强制走 CSS 变量；每套配色上线前跑一遍「代码 + 图表 + 公式」联合检查清单 |
| i18n 接入过晚导致返工 | 大量硬编码文案需返工 | v0.1 骨架阶段即接入，后续功能一律用 key |
| 编辑功能损坏用户文件 | 严重信任损失 | 原子写入 + `.bak` 备份 + 外部变更检测，三者缺一不发布 |
| 体积膨胀拖慢冷启动 | 核心卖点受损 | 严格执行 §5.3 懒加载，每个里程碑复测冷启动 |

## 0.1 两个必须知道的坑（本次实测发现）

### 坑一：每条 Bash 命令都要先加载 `~/.bashrc`

本项目的 Bash 是非交互式的，不会自动加载 `~/.bashrc`。Rust 与 MSVC 的 PATH 写在 `~/.bashrc` 里，因此**每条命令都要以 `source ~/.bashrc;` 开头**，否则会报 `cargo: command not found`。

```bash
# 正确
source ~/.bashrc; cargo --version

# 错误（不加载就是找不到）
cargo --version
```

同时注意：**PATH 条目必须用 POSIX 风格**。写成 `C:/Users/HajjiPC/.cargo/bin` 会被 PATH 的冒号分隔符切成 `C` 和 `/Users/...` 两段而失效，必须写 `/c/Users/HajjiPC/.cargo/bin`。

另外，MSVC 的 `bin\Hostx64\x64` 必须排在 `/usr/bin` **之前**，否则 Git Bash 自带的 `/usr/bin/link.exe`（coreutils 的 `ln`）会抢先命中，导致链接时使用错误的 `link`。

### 坑二：LNK1181 的真因是缺 `LIB` / `INCLUDE`，不是中文路径

> ⚠️ **本节经历过一次结论反转。** 早期版本把 LNK1181 归因为「项目路径含中文」，这个结论**已被实测推翻**。保留修订过程，是因为错误归因本身也值得看：它差点让我们为一个不存在的问题去改动项目结构。

在中文路径 `E:\workbuddy\MD阅读器` 下首次 `cargo build` 报错：

```
= note: LINK : fatal error LNK1181: 无法打开输入文件"kernel32.lib"
```

**当时的对照实验与推断**：

| 场景 | 结果 | 当时的推断 |
|---|---|---|
| cargo 默认（target 在中文路径下） | ❌ LNK1181 | — |
| `TMP`/`TEMP` 重定向到 ASCII 路径 | ❌ 仍失败 | 排除临时目录的影响 |
| `CARGO_TARGET_DIR` 指向 ASCII 路径 | ✅ 1.11 s 通过 | 得出「中间产物路径不能含中文」 |
| 源码在中文路径、输出产物到 ASCII 路径 | ✅ 通过 | 得出「读中文源码没问题」 |

四组数据看起来自洽，结论却**不成立**——加上 target 重定向之后仍然失败，这个反例直接把它否掉了。回头检查环境变量才看到：`LIB` 与 `INCLUDE` **都是空的**。链接器根本不知道去哪里找 `kernel32.lib`。

设置好这两个变量后重做对照：**源码、中间产物、输出全部在中文路径下，编译通过**。中文路径完全没有影响。

**真正的修复**（写入 `~/.bashrc`）：按已知路径直接写死这两个环境变量。

```bash
# MSVC 库与头文件搜索路径（Tauri 构建必需）
# 不设这两项，链接器会报 LNK1181: 无法打开输入文件"kernel32.lib"。
# vcvarsall.bat 在本机的 Bash / PowerShell 下无法可靠导出环境，故按已知路径直接写死。
# 注意：LIB/INCLUDE 用分号分隔、反斜杠路径，这是 Windows 原生格式，不要改成 POSIX 风格。
export LIB="C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\14.44.35207\lib\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\um\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\ucrt\x64"
export INCLUDE="C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\14.44.35207\include;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\ucrt;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\shared;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\winrt"
```

写入前**先逐个校验这八个目录确实存在**（版本号会随 VS 更新变化），不要照抄：

```bash
for d in \
  "/c/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/VC/Tools/MSVC/14.44.35207/lib/x64" \
  "/c/Program Files (x86)/Windows Kits/10/Lib/10.0.26100.0/um/x64" ; do
  [[ -d $d ]] && echo "OK  $d" || echo "MISSING  $d"
done
```

**为什么不用 `vcvarsall.bat`**：标准做法是用 VS 自带的 `vcvarsall.bat x64` 导出整套环境，但本机两种 shell 都拿不到——

- Git Bash：`cmd //c` 的参数会被吞掉，实际启动了一个交互式 cmd，只吐出 3 行 banner
- PowerShell：`>nul` 重定向被安全策略拦截（`cmd.exe nul redirection is not PowerShell syntax`）；去掉重定向后捕获到的变量数为 0

改用写死路径的代价是：MSVC 或 Windows SDK 升级后，路径里的版本号要手动跟着改。

### 坑三：构建产物落在工作区内会被沙箱拦截

清空 `LIB`/`INCLUDE` 的影响后，把 target 目录放回工作区内（`src-tauri/target/`）重新构建，cargo 大量删除与改写中间产物的操作被拒绝：

```
error: could not copy ... 拒绝访问。 (os error 5)
warning: ... to incremental directory ... 拒绝访问。 (os error 5)
```

涉及 `*.rcgu.o`、`lib.rmeta-link`、`build/*/output` 等几十个文件。**这与路径是否含中文无关**，是工作区内的频繁读写被沙箱挡住。

绕行方式是把产物目录挪到工作区之外，用 `src-tauri/.cargo/config.toml` 固化（对任何终端都生效，不必依赖环境变量）：

```toml
[build]
target-dir = "E:/workbuddy/md-reader-target"

# 关掉增量编译。增量目录会被拼成 \\?\ 长路径形式，同样触发「拒绝访问 (os error 5)」。
# 构建能完成，但每次都刷一条 warning 噪声。本项目 crate 很少，关掉增量的耗时差异可忽略。
incremental = false
```

注意：**target 重定向是为了绕沙箱，不是为了中文路径**。中文路径本身不需要任何绕行。

## 2. 安装顺序（重要）

**必须先装 MSVC，再装 Rust。**

原因：rustup 安装时会探测系统里的 C 链接器，探测到 MSVC 才会把默认宿主设为 `x86_64-pc-windows-msvc`。如果顺序反了，Rust 会认为系统没有链接器，后续 `tauri build` 会报 `linker not found`，需要重装工具链才能修复。

---

## 6. 常见问题排查

| 现象 | 原因 | 解决办法 |
|---|---|---|
| `rustc -V -v` 显示 `host: x86_64-pc-windows-gnu` | 先装了 Rust，后装 MSVC | 重装工具链：<br>`rustup toolchain uninstall stable`<br>`rustup toolchain install stable` |
| `tauri build` 报 `error: linker 'link.exe' not found` | 未刷新环境变量，或没在开发者终端里执行 | 重启终端；仍不行则从开始菜单打开 **Developer PowerShell for VS 2022** 再执行 |
| 编译报 `Windows SDK not found` | 安装时未勾选 SDK | 重新运行 `vs_BuildTools.exe` → 修改 → 勾选 Windows 11 SDK |
| VS 安装程序下载中断 | 网络不稳定 | 改用离线布局包：<br>`vs_BuildTools.exe --layout C:\vs2022 --add Microsoft.VisualStudio.Workload.VCTools --lang zh-CN`<br>下载完后运行 `C:\vs2022\vs_setup.exe` |
| Rust 下载极慢 | 境外源 | 设置镜像后重装：<br>`setx RUSTUP_DIST_SERVER https://mirrors.tuna.tsinghua.edu.cn/rustup`<br>`setx RUSTUP_UPDATE_ROOT https://mirrors.tuna.tsinghua.edu.cn/rustup/rustup` |
| `cargo: command not found` | 环境变量未刷新 | 关闭所有终端重开；仍不行则检查 `%USERPROFILE%\.cargo\bin` 是否在 PATH 中 |
